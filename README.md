# Веб-приложение для отслеживания платежей пользователей

Демонстрационное асинхронное веб-приложение в парадигме REST API.
Реализовано с целью продемонстрировать мои умения и мой подход к разработке и проектированию веб-приложений.

Тех. задание описано в `ASSIGNMENT.md`

## Стек

- СУБД `Postgres`
- `Python 3 (3.14)`
- Пакетный менеджер `uv`
- ORM для Python 3 `SQLAlchemy 2.x`
- Менеджер миграций для SQLAlchemy `alembic`
- Асинхронный веб-фреймворк `Sanic`
- Система контейнеризации `Docker`, `docker compose`
- Система тестирования `pytest`

## Установка и развертывание

Проект можно запустить 2 способами: с использованием Docker и без.

### Без использования docker compose

Необходимо установить требуемые зависимости - Python 3.14, uv, Postgres (не ниже 15 версии).

1. Установить зависимости Python

```
uv sync
```

2. Создать и настроить `.env.prod` и `.env.tests` в `.env` (см. примеры `.env.prod.example` и `.env.tests.example`)

3. В соответствие с конфигурацией создать БД и пользователя Postgres.

4. Собрать приложение при помощи

```
uv build
```

5. Установить приложение при помощи uv pip install

6. Прогнать миграции

```
uv run migrate-app
```

6. Запуск приложения:

```
uv run start-app
```

Запускает приложение на `8000` порту.

7. Запуск тестов:

```
uv run pytest
```

Требует настройки `.env.tests`

### С использованием docker compose

Необходимо установить Docker

1. Создать и настроить `.env.docker.prod` и `.env.docker.tests` в `.env` (см. примеры `.env.prod.example` и `.env.tests.example`)

2. Запустить приложение

```
docker compose up
```

Запускает контейнер и пробрасывает `8000` порт

Остановить контейнеры можно при помощи

```
docker compose down
```

3. Запустить тесты

```
docker compose -f docker-compose.test.yml run --rm tests
```

Остановить контейнеры можно при помощи

```
docker compose -f docker-compose.test.yml down
```

## Описание архитектуры приложения

### Приложение

Приложение придерживается слоистой архитектуры (насколько это применимо в Python)
Для внутренних слоев выдержана независимость от внешних.

Выделены следующие слои:

- ядро (доменные сущности и сценарии)
  - src/accounts/
    - core/
      - entities.py # сущности
      - use_cases/ # сценарии

- сервисный слой (для операций над ядром)
  - src/accounts/
    - service_layer/

- адаптеры (не совсем в классическом понимании - здесь это привязка внешних интерфейсов)
  - src/accounts/
    - adapters/

- входы (внешние интерфейсы)
  - src/accounts/
    - entrypoints/

Применяется Dependency Injection (для этого используются абстрактные классы для UnitOfWork и Repository)

### Тесты

Приложение хорошо покрыто тестами.

В приложении есть сквозные, интеграционные и юнит-тесты.

- Юнит-тесты тестируют конкретные методы, функции и сценарии
- Интеграционные тесты проверяют корректную работу с зависимостями (в частности, с SQLAlchemy)
- Сквозные тесты проверяют работу запущенного приложения
